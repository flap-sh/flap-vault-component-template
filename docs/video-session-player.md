# Video sessions in Tax Info

`VideoSessionPlayer` from `@/src/ui` plays MPEG-TS clips generated by [Flap Video Generator](https://docs.flap.sh/flap/developers/preview/flap-video-generator). It owns a pinned, lazy-loaded `mpegts.js@1.8.2` player. No direct package import, CDN script, manifest capability, browser-global access, or developer-selected gateway is required.

```tsx
import { VideoSessionPlayer, type VideoSessionClip } from "@/src/ui";

// Inside a component that already has the shared SDK and localized i18n:
const clips: readonly VideoSessionClip[] = session.map((clip) => ({
  videoCid: clip.videoCid,
  durationMs: clip.durationMs,
}));

<VideoSessionPlayer
  clips={clips}
  label={i18n.t("video.label")}
  fallback={<p>{i18n.t("video.unavailable")}</p>}
/>
```

Add `video.label` and `video.unavailable` to every declared locale in the package's `i18n.json`. `fallback` appears for an empty session, invalid CID/duration, missing Media Source Extensions, or a player/network error. Without a fallback the player area is empty in these states. Keep the current host-derived contract risk status before the player in ordinary Tax Info Vault UIs.

Read the ordered session through the shared SDK and the minimal project ABI. A fixed FlapAIProvider target must be declared in the binding's `externalContracts`; a Vault-owned proxy can instead use `context.vaultAddress`. Do not introduce component-owned RPC transports, polling faster than 5000 ms, or arbitrary network calls. The component does not read contracts or poll by itself.

`clips` accepts only `{ videoCid: string, durationMs: number }` entries. CIDs may come from contract reads. Runtime validation rejects URLs, paths, query strings, malformed CIDs, and non-positive/non-integer durations. The runtime constructs HTTPS IPFS URLs using its existing Flap gateway resolver. The gateway must serve the pinned clips with CORS enabled. Source URLs, custom loaders, headers, gateway selection, workers, and raw mpegts configuration are not exposed to package authors.

**Keep durations in milliseconds.** mpegts.js `MediaSegment.duration` uses milliseconds, matching FlapAIProvider's `durationMs`. The preview video-generator React example currently divides by 1000; do not copy that conversion into a runtime session. Only `video.currentTime` and player seek positions use seconds.

The native video controls are always visible while loading/ready, and inline playback is enabled. Autoplay defaults to off; pass `autoPlay` and optionally `muted` when explicitly needed. Browsers can reject autoplay; the user can still start playback through the controls. Background re-renders with equivalent clips do not rebuild the player. Appending clips rebuilds it, restores the current position after metadata loads, and preserves pause/play intent. Replacing, reordering or shortening the session starts a new timeline. Unmounting, clearing clips, load failures and playback errors tear down the player and listeners. Late asynchronous imports cannot resurrect a removed player.

MSE/Managed Media Source and the clip's audio/video codecs must be supported by the browser. Provide a localized fallback and test target iOS devices; the runtime does not transcode unsupported codecs. Direct `import("mpegts.js")`, raw remote `<video src>`, service workers, and arbitrary decoder/CDN loading remain outside the Vault source boundary.

## Release and consumer checks

This is an additive `./ui` export; runtime contract version 1 and the source-package format stay unchanged. The player and its lazy browser chunk are bundled in the runtime archive, so Workbench and beta need no separate mpegts dependency. Workbench discovers shared UI exports when building artifacts; beta forwards the complete runtime UI namespace to `__FLAP_VAULT_UI_RUNTIME__`.

Before merge, build a clean, committed feature-branch canary and validate the same `.tgz` in both consumers using `runtime:pack:canary` and `runtime:test:canary`. After merge, bump the template/runtime version, build and verify from official main, publish the normal runtime package, then pin **both Workbench and beta** to that released version and rebuild. The current published runtime does not gain this export until that coordinated upgrade. A private canary must not be published or used as source-ZIP release provenance.
