# 0.1.39 发布与升级说明

[English](0.1.39.md) · [版本规则](../versioning.md)

**状态：已发布到 npm latest，2026-10-23。** 来源：`78c355f080a60770cfd64d71d94c525204d61583`。公开归档与从干净官方 main 构建的审阅发布包一致。功能分支私有 canary 仍不可发布，也不能替代正式发布来源。

## FSI endpoint 兼容

本版本在保留 `https://bsc-debug.butterfly.army/fsi/v1` 的同时，增加 `https://fsi.taxed.fun/fsi/v1`。在 `manifest.endpoints` 中用字符串或数组声明需要使用的根前缀。只声明旧地址时继续请求旧地址；两个地址都声明时，`sdk.readFsi(relativePath, params)` 固定选择 `fsi.taxed.fun`，不受数组顺序影响。请求失败不会自动切换到另一个域名。

公开 SDK 调用方式不变。两个域名均保留精确 HTTPS origin、`/fsi/v1` 路径边界、manifest 声明和人工审核要求。读取使用 GET，省略凭证与 referrer，拒绝重定向，并校验路径和查询参数编码。审核记录展示实际选中的 endpoint。已发布的 `0.1.38` 只接受旧地址。

本次不增加依赖或 manifest 字段。Runtime contract version 1、Vault 源码格式 6 / E2E report v2，以及独立 App 源码格式 7 / E2E report v3 均保持不变。

## 发布验证与发布

使用 Node.js 24 与 Yarn 1.22。在干净的官方仓库副本运行：

```bash
yarn test:fsi
yarn test:flap-wallet
yarn run check
yarn vault:check:selftest
yarn test:runtime-package-mode
yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

使用 fork 的维护者需设置 `FLAP_TEMPLATE_FRESHNESS_REF=upstream/main`，并确保 `upstream` 指向官方仓库。正式打包要求当前官方 main 最新提交、匹配的 npm 来源历史与干净的已提交源码。不要绕过 freshness 校验，也不要发布私有 canary。

检查生成的 package 和 runtime contract：版本为 `0.1.39`，`gitHead` 为本次审核的官方 main 提交，使用公开 `latest` 发布配置，且没有 private 标记或 canary 元数据。发布前核对 exports、生成包 README 和 tarball，并发布同一份归档。记录 SHA-256 与 npm integrity，再核对 registry 版本、`gitHead`、下载字节与 `latest` tag；保留既有 `next` tag。

## 宿主升级

Workbench 和 Flap 主站精确固定 `@flapsdk/vault-runtime@0.1.39`。Workbench 还须部署匹配的 FSI 校验器；只升级 npm 依赖不会更新复制在本地的校验策略。接收使用新域名的源码包前，验证只声明新地址、只声明旧地址、同时声明两者、审核展示的 endpoint，以及未声明时的阻断行为。

App 开发者更新官方 main 模板，并按已发布 runtime 的精确身份重新生成检查、E2E、源码打包和验证证明。SDK 发布不会部署消费项目，也不代表 artifact 获准上线。保留 `0.1.38` 历史发布与 next 弃用记录。
