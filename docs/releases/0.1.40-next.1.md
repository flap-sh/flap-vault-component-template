# 0.1.40-next.1 device sensor test release

Prepared for npm `next` on 2026-10-24. This is an explicitly requested testing release from official `next`; stable `latest` remains `0.1.39`. The source includes the reviewed device implementation commit `b1d5cf402576b01efbe5f2708486e8ee558d5d68` and current main/latest functionality.

## Device API

The Runtime advertises `sdkFeatures.deviceSensors=1` and exports `DEVICE_SENSORS_VERSION=1`, `useGeolocation`, `useDeviceMotion` and `useDeviceOrientation`. Both Vault UI and standalone Mini App providers receive the shared, lazy device service. Host-only factories provide real browser access or explicitly labeled preview mocks; components declare only the needed `deviceCapabilities` and request access from user actions.

Permission grants are separate from valid readings. Handle refusal, unsupported browsers, missing hardware, policy restrictions, data timeout, cancellation and background pauses. Supply a business fallback such as click/touch input instead of shake/tilt. Existing manifests without declarations retain their behavior and do not trigger device access. See [device integration](../device-sensors.md) and [中文说明](../device-sensors.zh-CN.md).

## Testing installation

```sh
yarn add --exact @flapsdk/vault-runtime@0.1.40-next.1
```

Use the exact prerelease in an isolated testing branch or checkout. Main-site and Workbench production pins are separate. Workbench additionally needs the matching device schema and copied policy/provenance; updating only the npm dependency does not authorize new source packages. Private canaries are not publishable packages or source ZIP provenance.

## Publication checks

From clean committed source at the fetched official next head:

```sh
FLAP_TEMPLATE_FRESHNESS_REF=upstream/next yarn runtime:package:next
yarn runtime:verify-package
yarn test:runtime-provider --package
```

Pack only the verified `dist/vault-runtime` directory and publish that same archive with explicit `--tag next --access public`. Confirm the package version, Git SHA, feature marker, public next publish configuration and absence of private/canary fields. After publishing, compare the registry integrity and downloaded archive with the local tarball, and confirm `latest` remains `0.1.39`.

Automated coverage uses deterministic sensor environments and explicit mocks. iPhone Safari, Android Chrome and the supported wallet WebViews still require real-device verification.
