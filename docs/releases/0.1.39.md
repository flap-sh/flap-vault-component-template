## FSI endpoint compatibility

This release adds `https://fsi.taxed.fun/fsi/v1` alongside `https://bsc-debug.butterfly.army/fsi/v1`. Declare the intended root prefix in `manifest.endpoints`, as a string or array. A declaration containing only the legacy prefix preserves legacy routing. When both are declared, `sdk.readFsi(relativePath, params)` selects `fsi.taxed.fun` regardless of array order. Failed requests do not fall back to the other host.

The public SDK call is unchanged. Both hosts retain exact HTTPS origin and `/fsi/v1` path boundaries, required manifest declarations and human review. Read requests use GET, omit credentials and referrers, reject redirects and validate paths and query encoding. Review evidence records the endpoint actually selected. Published `0.1.38` accepts only the legacy prefix.

No dependencies or manifest fields are added. Runtime contract version 1, Vault source format 6 / E2E report v2 and standalone App format 7 / E2E report v3 remain unchanged.

## Release validation and publication

Use Node.js 24 and Yarn 1.22. From the clean official clone, run:

```bash
yarn test:fsi
yarn test:flap-wallet
yarn run check
yarn vault:check:selftest
yarn test:runtime-package-mode
yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

Fork maintainers must set `FLAP_TEMPLATE_FRESHNESS_REF=upstream/main`, with `upstream` pointing to the official repository. Stable packaging requires the current official main head, matching npm ancestry and clean committed source. Do not bypass freshness or publish a private canary.

Inspect the generated package and runtime contract: version `0.1.39`, the reviewed official-main `gitHead`, public `latest` publish configuration, no private flag and no canary metadata. Verify exports, generated README and the tarball before publishing the same archive. Record its SHA-256 and npm integrity, then confirm the registry version, `gitHead`, downloaded bytes and `latest` tag match. Preserve the existing `next` tag.

## Host rollout

Pin exact `@flapsdk/vault-runtime@0.1.39` in Workbench and the Flap host. Workbench must also deploy the matching FSI checker; updating only the npm dependency does not update a copied validator policy. Verify new-only, legacy-only and dual declarations, the endpoint shown in review, and missing-declaration rejection before accepting source packages that use the new host.

App authors update the official main template and regenerate their current check, E2E, source-package and verification proof against the published runtime identity. SDK publication does not deploy consumers or approve an artifact. Keep the `0.1.38` publication and historical next deprecation records unchanged.
