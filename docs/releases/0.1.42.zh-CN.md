## 行为与兼容性

新增以下精确查询前缀：

```text
https://bsc-testnet-debug.butterfly.army/fsi/v1
```

SDK 和模板源码校验器识别三个 FSI 根前缀。声明多个前缀时，按以下固定优先级选择，与 manifest 数组顺序及 `chainId` 无关：

1. `https://fsi.taxed.fun/fsi/v1`
2. `https://bsc-debug.butterfly.army/fsi/v1`
3. `https://bsc-testnet-debug.butterfly.army/fsi/v1`

现有主网优先级及 URL 构造器的旧默认地址保持不变。测试网 artifact 应在 `manifest.endpoints` 中仅声明测试网 FSI 根前缀。`sdk.readFsi(relativePath, params)` 使用已声明的根前缀；切换钱包或 SDK 链不会自动切换 FSI 部署。请求失败时不会重试其他域名。

```json
{ "endpoints": "https://bsc-testnet-debug.butterfly.army/fsi/v1" }
```

根前缀声明不得带查询参数，可带末尾斜杠。仅声明域名或某个子接口不能满足 `sdk.readFsi` 授权要求。放行范围仅包括各自精确 HTTPS origin 下的 `/fsi/v1` 及其子路径，不增加 `butterfly.army` 泛域名权限，也不放行 `/fsi/versions`、`/fsi/v10`、图片、导航或 frame。凭据、fragment、非默认端口、相似域名、原始或编码的点路径段及编码的路径分隔符仍在 URL 归一化前拒绝。

SDK 查询继续使用 GET、省略凭据、拒绝重定向、不发送 referrer，并采用 no-store 缓存策略。直接静态或模板 FSI `fetch` 仍须显式填写字面量 `method: "GET"`、`credentials: "omit"`、`redirect: "error"`、`referrerPolicy: "no-referrer"`；可选 `cache: "no-store"`，继续禁止自定义 headers、body 及选项覆盖。原生 fetch 仅允许通过全局 `encodeURIComponent` 编码的查询值动态变化；动态路径使用 `sdk.readFsi`。manifest 声明和端点人工审核证据仍然必须保留。详见 [FSI 使用方式与边界](../sdk.md#fsi-queries)。

本次无新增依赖、公共 SDK API、export、manifest 字段或钱包权限。SDK 签名、runtime contract version 1、Vault 源码包格式 6 / E2E v2、独立 App 源码包格式 7 / E2E v3 均不变。npm runtime 包含 SDK 实现，源码校验规则另行部署。

## 后续正式发布步骤

正式发布是合并后由维护者授权执行的独立步骤。

1. 审核 PR #49 的功能、`0.1.42` 版本及发布范围，并合入官方 `main`。
2. 使用 Node.js 24 和 Yarn 1.22，从刚 fetch 的官方 `main` 精确 HEAD 所对应的干净已提交源码执行。保留 Git/npm freshness 和来源校验。官方 remote 若名为 `upstream`，正式构建选择 `FLAP_TEMPLATE_FRESHNESS_REF=upstream/main`。
3. 完成所需发布验证，再运行 `yarn runtime:package`、`yarn runtime:verify-package`、`yarn test:runtime-provider --package`。检查生成的 `dist/vault-runtime/package.json`、`runtime-contract.json`、README 及 exports；要求版本为 `0.1.42`、`gitHead` 为实际官方 main 构建源码、公有 `latest` publish 配置，且不存在 private 或 canary 元数据。
4. 从已核验的 `dist/vault-runtime` 目录生成 `.tgz`，记录 SHA-256 和 npm integrity，然后将同一个已核验归档发布到 `latest`。不得从模板根目录、功能分支或私有 canary 发布，也不得在核验后改写生成包的 version、`gitHead`。
5. 核对 registry 版本、`latest` tag、`gitHead`、integrity 以及下载包字节与已核验归档一致，并确认 `next`、`routing` 保持原值。只有完成这些核对后，才能用真实发布证据填写下表并将 `0.1.42` 状态改为已发布。
