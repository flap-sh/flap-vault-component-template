## 范围与兼容

模板 [PR #36](https://github.com/flap-sh/flap-vault-component-template/pull/36) 已合并。它允许对合法的严格 `taxed.fun` 子域名（含多级子域）使用固定 HTTPS host/path，并通过未被局部遮蔽的全局 `encodeURIComponent` 编码动态 query 值。仍需具体 manifest 端点声明、字面量安全 GET 选项和人工审核。动态 host/path、伪域名、不安全请求选项及全局编码函数改写仍会阻断。检查器还识别命名函数表达式的作用域，防止局部编码函数冒充全局函数。

SDK 的公开 exports 与 API 签名保持不变。Runtime contract version 1、Vault 源码格式 6 / E2E report v2，以及独立 App 格式 7 / E2E report v3 均保留现有约定。

原生 fetch 放行规则位于模板及 Workbench 的**源码校验器**。npm runtime 归档仅包含编译后的 SDK/UI/host/server 模块、类型声明、source map、runtime contract 和 README，不包含 `vault-check.mjs` 或 `taxed-endpoint-policy.mjs`。只发布或升级 SDK 不会部署白名单。`sdk.readFsi` 保持既有端点、声明规则与路由，没有新增任意 fetch 的 SDK API。详见 [taxed.fun 端点策略](../taxed-endpoints.md)。

模板 CI runner 固定为锁定 Playwright 版本支持的 Ubuntu 24.04，避免跟随到不受支持的 Ubuntu 26.04 镜像。既有 CI 检查保持完整。

## 发布验证

先准备并合并版本及文档发布 PR，再使用 Node.js 24、Yarn 1.22，在精确匹配已获取的官方 `main` 最新提交、且干净的 checkout 中构建。功能分支 canary 是私有测试包，不可发布。如果 `origin` 是 fork，设置 `FLAP_TEMPLATE_FRESHNESS_REF=upstream/main`，并确保 `upstream` 指向官方 Flap 仓库。不得绕过 freshness、npm 祖先关系、干净源码或包身份检查。

运行并记录以下针对性检查；这是发布步骤，**不代表已经全部通过**：

```bash
yarn test:fsi
yarn test:runtime-package-mode
yarn test:release-channel
yarn run check
yarn vault:check:selftest
yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

本次按维护者既定要求跳过模板完整 `yarn ci`，也不等待耗时较长的 GitHub CI。发布记录必须保留此限制，不能报告完整 CI 通过。发布相关针对性检查与生成包验证仍必须通过。

核对生成的 `dist/vault-runtime/package.json`、`runtime-contract.json`、README 与 exports。要求版本为 `0.1.40`，`gitHead` 为本次审核的官方 main 提交，`publishConfig` 为 `{ "access": "public", "tag": "latest" }`，且没有 private 标记或 canary 元数据。README 必须说明真实包表面，区分源码校验策略与 npm 运行时代码。

验证成功后，从已核验的 `dist/vault-runtime` 目录打包 `.tgz`，记录 SHA-256 与 npm integrity，并将同一归档公开发布到 `latest`。不得从模板根目录发布，也不得发布私有 canary。发布后核对 registry 版本、`gitHead`、integrity、下载归档字节以及 `latest=0.1.40` 是否与本地审阅制品一致，并再次确认 `next` 与 `routing` 保持上方身份。
