## 本次行为

独立 Mini App v2 增加 `useMiniAppRouter()`，提供相对应用根目录的 `pathname`、
只解码一次的不可变 `segments`、`search` 和 `push/replace/back`。宿主注入浏览器或
内存适配器。`/apps/{slug}/bnb/{ca}`、`/apps/{slug}/settings` 等通用子路径复用同一
已审核产物、钱包及会话；路径不授予新的合约权限，保留原有目标合约和 resolver 策略。

浏览器导航保持应用状态和框架 history，支持直达、刷新、原生前进后退并拒绝路径逃逸。
Workbench 使用独立内存历史。源码检查器要求路由 import 使用支持该能力的 Runtime。
应用调用 `useMiniAppRouter()` 时，SDK 兼容层检查路由版本及 export，hook 还要求宿主
提供适配器。旧应用无需适配器并保留兼容。

不新增依赖或 manifest 字段。Runtime contract version 1、Vault 源码格式 6 /
E2E report v2、独立 App 源码格式 7 / E2E report v3 保持不变。
能力标记为 `MINI_APP_ROUTING_VERSION=1` 与 `sdkFeatures.miniAppRouting=1`。

## 合并前验证

使用 Node.js 24 和 Yarn 1.22，在从官方 main 建立的子路由独立分支运行：

```bash
yarn test:mini-app-routing
yarn test:release-channel
yarn test:runtime-package-mode
yarn run check
yarn runtime:pack:canary
```

canary 构建要求源码干净且已提交，生成不可公开发布的 private 包，验证打包后 Provider/hook
共享上下文、缺少适配器时明确报错、宿主专用适配器与生成包 README，并记录 tarball 哈希。
在两个消费项目中验证这份精确 canary，包括浏览器路由及生产构建。canary 不能替代源码 ZIP
来源，也不能公开发布。普通 CI 和独立 Mini App v2 工作流都包含子路由测试。

## 尚待满足的发布条件与证据

合入官方 main 前，维护者必须具备可用的 npm 发布身份。发布仍等待该认证条件以及经过审核的
官方 main 发布构建。本次不增加受信发布工作流；条件未满足时，保持官方 main 与 npm tags 不变。

获准发布后合并已审核分支，使用刚获取的精确官方 main 提交和干净副本。使用 fork 的维护者
将 `FLAP_TEMPLATE_FRESHNESS_REF=upstream/main` 指向官方上游：

```bash
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

检查版本为 `0.1.40`、`gitHead` 为审核后的 main 提交、发布配置为公开 `latest`、
路由 exports 和 README 正确，且不存在 private/canary 元数据。仅发布核验后的归档。
正式来源提交、SHA-256 和 npm integrity 均**尚待发布后补充**，不能用功能分支 canary
哈希替代。核对下载字节、registry 身份及 `latest=0.1.40`，并确认
`next=0.1.40-next.1` 保持不变。
