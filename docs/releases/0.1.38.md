# 0.1.38 release preparation

[简体中文](0.1.38.zh-CN.md) · [Main/latest migration](../main-migration.md)

**Status: published on npm latest, 2026-10-23.** Source: `1220ee9813f73eafd434decb365a08ae6a681445`. All eight historical next versions are deprecated and remain downloadable. Vault UI and Mini App v2 share official main/latest and one runtime. Existing v1 maintenance remains compatible.

## Release validation

Use a clean committed checkout at the fetched official main head, Node 24 and Yarn 1.22. Fork maintainers set the official upstream reference:

```bash
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn test:release-channel
yarn test:runtime-package-mode
yarn check
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn app:check standalone-example
yarn app:e2e standalone-example
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn app:build
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

The official clone can use the default origin/main. Inspect `dist/vault-runtime/package.json` and `runtime-contract.json`: version `0.1.38`, the reviewed main gitHead, `publishConfig: { access: "public", tag: "latest" }`, no private flag and no canary metadata. Verify exports, README and archive integrity before publishing. Stable packaging rejects dirty source and prerelease/channel mismatches. An explicitly authorized future next release still uses its isolated next path; it is not needed for App development.

## Developer update and host rollout

Confirm registry `latest=0.1.38`, source gitHead and archive integrity. App ZIPs must not reuse old latest `0.1.37`, historical next or private canary provenance. Regenerate from the matching official main source:

```bash
yarn app:check standalone-example
yarn app:e2e standalone-example
yarn app:package standalone-example
yarn app:verify-package dist/standalone-example.zip
```

The unpublished-runtime gate was verified before release. After publication, real App packaging and normal verification passed using registry latest `0.1.38` and source `1220ee9813f73eafd434decb365a08ae6a681445`. CI continues to use private canaries for candidate validation; those are never published or accepted as App ZIP provenance.

Pin and deploy exact `@flapsdk/vault-runtime@0.1.38` in Workbench and the main host, including validation-contract inputs. Test real uploads and host wallet integration before accepting new submissions. The App manifest, source format 7, E2E schema 3 and human-review requirements stay unchanged. Vault UI and App remain separate deliverables.

All eight historical next versions in [the deprecation record](../main-migration.md#stable-upgrade-and-preview-deprecation) are now deprecated, with upgrade messages pointing to stable `0.1.38`. Downloads remain available. Consumer deployment and App approval remain separate steps.
