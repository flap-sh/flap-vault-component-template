# 0.1.40-next.3 testing release

[简体中文](0.1.40-next.3.zh-CN.md)

Prepared on 2026-10-26 for the coordinated device-sensors testing rollout. Publication identity will be recorded after public registry and archive verification. Stable npm `latest` remains `0.1.39`.

This fixes a source-package integration gap in `next.2`: street-map Apps declared `mapCapabilities` in the manifest, but the template did not copy it into the package marker and metadata. Workbench correctly rejected that mismatch. The corrected writer preserves the optional declaration, and the verifier validates all three declarations and their exact agreement. Existing packages without maps remain compatible; package formats and Runtime contract version are unchanged.

Runtime APIs remain the same as [next.2](0.1.40-next.2.md): shared location/motion/orientation hooks, Mini App subroutes and the fixed `FlapStreetMap` UI component. This new preview version provides matching published provenance for the corrected packager/verifier; it does not relax official-source, published-identity, E2E or schema checks.

After publication, both receiving projects must pin this exact package and matching Workbench validation provenance before testing new uploads. Deploy only to the intended testing environment. Stable Vault UI/source ZIP development continues to use official main/latest. The existing explicit next source-ZIP path supports standalone Mini App v2 only; legacy Vault UI/v1 feature work can be checked in local preview and must wait for the coordinated stable rollout for ordinary source submission.

See the [developer integration guide](../device-map-integration.zh-CN.md) for the complete map/GPS example, permissions, fallbacks and exact testing commands. Device IDs, persistent claim records and anti-abuse enforcement are not part of this release.

## Validation

Run the focused map source-package/verifier regressions, sensors, device policy, routing/release-channel checks, typecheck and lint. Build from clean committed source matching official `upstream/next`:

```sh
FLAP_TEMPLATE_FRESHNESS_REF=upstream/next yarn runtime:package:next
yarn runtime:verify-package
yarn test:runtime-provider --package
```

Publish only the verified archive to `next`, then compare the public archive bytes, gitHead and integrity and confirm `latest=0.1.39` is unchanged. Do not publish a private canary or change the stable source-package gates.
