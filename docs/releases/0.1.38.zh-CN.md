## 发布验证

使用干净且已提交、与最新官方 main HEAD 一致的工作区，以及 Node 24、Yarn 1.22。使用 fork 时选择官方 upstream：

```bash
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn test:release-channel
yarn test:runtime-package-mode
yarn check
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn app:check standalone-example
yarn app:e2e standalone-example
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn app:build
FLAP_TEMPLATE_FRESHNESS_REF=upstream/main yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

直接克隆官方仓库时可使用默认 origin/main。检查 `dist/vault-runtime/package.json` 与 `runtime-contract.json`：版本 `0.1.38`、经验证的 main gitHead、`publishConfig: { access: "public", tag: "latest" }`，没有 private 标记或 canary 元数据。发布前核对导出、README 和归档完整性。正式打包会拦截未提交源码及版本/通道不匹配。未来明确授权的 next 发布仍使用独立 next 路径，App 开发无需再发布 next。

## 开发者更新与宿主上线

确认 registry 的 `latest=0.1.38`、来源 gitHead 与归档完整性。App ZIP 不得沿用旧 latest `0.1.37`、历史 next 或私有 canary 证明。从匹配的官方 main 重新生成：

```bash
yarn app:check standalone-example
yarn app:e2e standalone-example
yarn app:package standalone-example
yarn app:verify-package dist/standalone-example.zip
```

发布前已验证未发布 runtime 的拦截。发布后，真实 App 打包和普通验证已通过，使用 registry latest `0.1.38` 及来源 `1220ee9813f73eafd434decb365a08ae6a681445`。CI 继续使用私有 canary 验证候选源码，canary 不发布，也不能作为 App ZIP 来源证明。
