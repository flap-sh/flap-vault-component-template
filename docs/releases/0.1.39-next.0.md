# 0.1.39-next.0 — Mini App v2 dynamic IPFS

[简体中文](0.1.39-next.0.zh-CN.md)

Published on npm `next` on 2026-10-15, with source `gitHead` `48bb8c2d7a6ef14278915d61b08b3c00b55d5fd6`. Stable `latest` remains `0.1.37`.

- Merge official main (`ad40bab`, stable 0.1.37) into `feat/mini-app-v2`.
- Add controlled dynamic `IpfsImage`, escaped `IpfsText`, and bounded `sdk.readIpfsText(cid, path?)` to Mini App v2 and Vault UI.
- Expose reviewed `sdk.readFsi(path, params?)` on the explicit-chain SDK, retaining the fixed platform endpoint boundary.
- Preserve shared wallet actions, CopyButton, existing Vault UI and legacy App compatibility.

Vault UI uses `useFlapSdk()`; Mini App v2 uses `useFlapSdk({ chainId: 56 })`. Import shared components from `@/src/ui`; do not install a second SDK in the App folder. Follow [the IPFS guide](../ipfs-content.md) and [v2 quickstart](../mini-app-v2-quickstart.md).

Upgrade the exact runtime in both Flap hosts and testing Workbench, and deploy the matching Workbench checker. The npm dependency alone does not update checker policy. Dynamic sources require human review. Source ZIPs still require current official template provenance and successful guest/connected E2E on PC/iPad/H5. No package-format changes, additional dependencies or broader transaction permissions are introduced.

Pre-publication validation uses a private canary with both consumers. Browser content fixtures verify rendering, CID changes, escaped text and rejected inputs; they do not prove live Pinata availability or project-specific transactions.
