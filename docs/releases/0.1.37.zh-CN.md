# 0.1.37 — 动态 IPFS 内容支持

[English](0.1.37.md)

本版对应 [PR #24](https://github.com/flap-sh/flap-vault-component-template/pull/24)
已合并的动态 IPFS 能力。源码版本更新或发布准备 PR 不代表 npm 已发布；
升级生产依赖前须核对 npm 版本元数据。

## 变更

- `sdk.readIpfsText(cid, path?)` 返回有大小限制的 UTF-8 文本或 JSON 字符串。
- `IpfsText` 显示转义纯文本，处理加载、失败及 CID 变化。
- `IpfsImage` 接受动态裸 CID，包括 FSI 返回值和 SDK 上传结果。
- 能力标识为 `IPFS_CONTENT_VERSION === 1` 和
  `runtime-contract.sdkFeatures.ipfsContent === 1`，动态来源仍须人工审查。

用法和限制见 [API 说明](../ipfs-content.zh-CN.md)。固定平台网关、安全 CID/路径、
不跟随重定向、不携带凭据、有界读取和文本转义均保持有效。
`IpfsBackground` 仍只接受静态 CID，`NftMetadataImage` 保持独立路径。
本次发布准备不新增依赖、manifest 字段或合约写入权限，也不修改 schema、源包格式
及 runtime contract 版本。

## 兼容与上线顺序

| 运行时 | FSI query 与已审核的 resolved `execute` | IPFS 文本 API/组件及动态图片检查 |
| --- | --- | --- |
| `0.1.35` | 不支持 | 不支持 |
| `0.1.36` | 支持 | 不支持 |
| `0.1.37` | 支持，范围不变 | 配合对应 Workbench 策略后支持 |

npm 发布后：

1. 用 Yarn 将 Workbench 和主站的 `@flapsdk/vault-runtime` 精确升级到 `0.1.37`，
   同步提交 lockfile；不可将私有 canary 记作正式依赖。
2. 部署对应 Workbench IPFS 静态检查和运行时能力检查；只更新 npm 包不会替换
   Workbench 自身的检查器脚本。
3. 两个宿主都升级后，再接收使用新文本/动态图片的 UI 包。组件继续使用
   `@/src/sdk` 和 `@/src/ui` 别名。
4. 联调分页 FSI 返回的文本/图片 CID、加载/失败状态及 CID 切换。已有上传服务
   配置好后，可用 SDK 上传测试内容生成 CID，无须项目方提供业务数据。

读取由浏览器访问平台网关，网关必须能提供已 pin 的内容并允许浏览器请求。
读取不新增宿主路由，也不需要 Pinata 凭据；上传继续依赖既有
`/api/runtime/upload` 服务及服务端配置。自动化上传样例使用模拟服务，
不能替代真实上传及网关联调。

## 维护者发版

按 [版本流程](../versioning.md#stable-release-workflow)，先合并版本与文档更新，
从官方 `main` 的准确提交构建、验证并测试生成的运行时入口，再打包已验证目录。
获得维护者发布授权后才发布 npm，并核对 registry 版本、`gitHead`、integrity
及 dist-tags 与本地归档一致；保持 `next` 标签不变，禁止发布私有 `-canary.*` 包。
