## Scope and compatibility

Template [PR #36](https://github.com/flap-sh/flap-vault-component-template/pull/36) is merged. It allows fixed HTTPS hosts and paths on valid strict `taxed.fun` subdomains, including multiple subdomain levels, with dynamic query values encoded by the unshadowed global `encodeURIComponent`. Concrete manifest endpoint declarations, literal safe GET options and human review remain required. Dynamic hosts or paths, lookalike domains, unsafe request options and encoder mutation remain blocked. The checker also recognizes named function-expression scope, preventing a local encoder from impersonating the global encoder.

The public SDK exports and API signatures remain unchanged. Runtime contract version 1, Vault source format 6 / E2E report v2, and standalone App format 7 / E2E report v3 retain their existing contracts.

The new native-fetch allowance is implemented in template and Workbench **source checkers**. The npm runtime archive contains compiled SDK/UI/host/server modules, declarations, source maps, its runtime contract and README; it does not contain `vault-check.mjs` or `taxed-endpoint-policy.mjs`. Publishing or upgrading this SDK alone does not deploy the allowlist. `sdk.readFsi` keeps its existing endpoints, declaration rules and routing; no new arbitrary-fetch SDK API is introduced. See [taxed.fun endpoint policy](../taxed-endpoints.md).

The template CI runner is fixed to Ubuntu 24.04, supported by the locked Playwright version, rather than following an unsupported Ubuntu 26.04 image. The existing CI checks remain intact.

## Release validation

Prepare and merge the version/documentation release PR, then use Node.js 24 and Yarn 1.22 in a clean checkout at the fetched official `main` head. A feature-branch canary is private and cannot be published. If `origin` is a fork, select `FLAP_TEMPLATE_FRESHNESS_REF=upstream/main` with `upstream` pointing to the official Flap repository. Do not bypass freshness, npm ancestry, clean-source or package-identity checks.

Run and record these targeted checks; this list is a release procedure, not a claim that they have already passed:

```bash
yarn test:fsi
yarn test:runtime-package-mode
yarn test:release-channel
yarn run check
yarn vault:check:selftest
yarn runtime:package
yarn runtime:verify-package
yarn test:runtime-provider --package
```

Full template `yarn ci` and waiting for its long GitHub CI are skipped for this release under the maintainer instruction. Keep this limitation in the release record and do not report full CI as passing. Targeted release and generated-package checks still must pass.

Inspect the generated `dist/vault-runtime/package.json`, `runtime-contract.json`, README and exports. Require version `0.1.40`, the reviewed official-main `gitHead`, `publishConfig: { "access": "public", "tag": "latest" }`, and no private flag or canary metadata. The README must describe the actual package surface and distinguish source-checker policy from packaged runtime behavior.

## Publication and evidence

After successful validation, pack the verified `dist/vault-runtime` directory into a `.tgz`, record its SHA-256 and npm integrity, and publish that same archive publicly under `latest`. Do not publish from the root template directory or a private canary. Confirm the registry version, `gitHead`, integrity, downloaded archive bytes and `latest=0.1.40` against the checked artifact; recheck that `next` and `routing` retain the identities above.

Only after those checks succeed should the current status and this document be changed to published and supplied with the actual release identity. Preserve the historical [0.1.39 publication evidence](0.1.39.md); it is not evidence for `0.1.40`.

## Consumer and checker rollout

Workbench [PR #43](https://github.com/flap-sh/flap-artifact-workbench/pull/43) is not merged or deployed. A matching Workbench checker must be reviewed, merged and deployed separately before intake can accept source using the new allowance. SDK publication neither merges that PR nor changes the receiving checker.

Host/runtime exact dependency pins and their lockfiles are separate rollout work after publication. Source authors update the official template and regenerate current check, E2E, source-package and verification evidence against the published identity. Unpublished `0.1.40` cannot be used as a stable App ZIP's runtime provenance. Endpoint review and artifact approval remain required. Real service responses, browser CORS and the original business request have not been verified without a sanitized request example.
