# 0.1.40-next.3 测试版

[English](0.1.40-next.3.md)

于 2026-10-26 准备用于主站、Workbench 和模板的传感器测试分支联调，公开发布身份将在注册表和归档核验后补充。正式 npm `latest` 保持 `0.1.39`。

本版修复 `next.2` 的源码打包遗漏：地图小程序的 manifest 声明了 `mapCapabilities`，但模板没有把该字段写入 ZIP 的 marker 和 metadata，导致 Workbench 正确拒绝这个不一致的包。现在两处都会保留可选声明，verifier 会检验三处声明的合法值与一致性。无地图旧包保持兼容，不变更包格式或 Runtime 合约版本。

Runtime API 与 [next.2](0.1.40-next.2.zh-CN.md) 相同，仍包含共享定位/运动/方向、Mini App 子路由和固定的 `FlapStreetMap`。新测试版本为修复后的打包器和校验器提供匹配的公开来源，不放宽官方源码、发布身份、E2E 或 schema 检查。

发布后，两个接收端要固定相同的本版依赖，Workbench 同步对应的 validation provenance，再在测试环境联调上传。正式 Vault UI/源码 ZIP 开发仍遵循官方 main/latest；现有显式 next 源码 ZIP 流程只支持独立 Mini App v2。旧 Vault UI/v1 的新能力可在本地预览测试，普通源码提交需等待配套正式版本。

可直接转发给开发者的[地图与传感器接入说明](../device-map-integration.zh-CN.md)包含 manifest、代码示例、权限、降级、测试打包和验收步骤。本版不提供持久化领取记录、设备号或防刷服务。

验证包括地图源码包/校验器回归、传感器、设备策略、路由/发布通道、typecheck、lint，以及官方 next 干净提交上的 Runtime 构建、包校验和打包 Provider 浏览器测试。发布后核对公开归档字节、gitHead 和 integrity，并确认正式 `latest=0.1.39` 未变化；详见[英文检查命令](0.1.40-next.3.md#validation)。
